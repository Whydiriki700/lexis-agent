# Planning and Task Breakdown

1. State the outcome in one sentence before listing steps.
2. Break the work into steps that each end with something checkable: a file, a test result, a verified behavior.
3. Order by dependency; a step that needs another step's output comes after it.
4. Name the risk in each step that could fail, and how you will know.
5. Keep the plan visible while working; mark steps as they finish, never retroactively.
6. If the plan stops matching reality, say so and replan out loud instead of drifting.
