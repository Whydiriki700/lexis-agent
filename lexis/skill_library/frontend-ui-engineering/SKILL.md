# Frontend UI Engineering

The face is part of the product. If a page could belong to any product, it belongs to none.

1. Match the existing design system first: its colors, spacing, and components. Invent only what the system lacks.
2. Design every state, not just the happy one: loading, empty, error, and long content are first-class screens.
3. Real data and real copy only. Placeholder text and stock-looking filler are defects, not drafts.
4. Verify in a real browser at real sizes, including the smallest screen the product promises to support.
5. Accessibility is not a pass at the end: labels on controls, visible focus, contrast that survives daylight.
6. Keep the interface honest: nothing on screen claims a state the system has not actually reached.
